The four open items

Each traced to a code-confirmed root cause. Status chip shows whether it builds now or waits on a gate.

Test 10 — typed words droppedShip now
Cause: category tiles start a flow with no free-text arg (views.js:177), so the handler's typed words never reach the ticket. The suggestion chip already carries them.
Fix: a thin startTileFlow wrapper carries the words from state (mirrors the chip) + echo them on the confirmation card.
Test 11a — auto-P1Gated · James+Sam
Cause: P1 is hard-coded in three flows (fine as-is). Welfare flows don't capture the qualifying signal (vulnerability / active-safety), so it's new logic, not routing.
Fix: new in-flow qualifying step routes to P1; a p1Reason tag; an audited, reason-tagged escape-hatch. Flow selection is your call (D-11a-1).
Test 11b — real SMS gatewayGated · OOHDASH-73
Cause: provider is in log mode; the Twilio path already exists. Enabling is a config/secret op, not new code.
Fix: a startup config-guard makes a half-configured gateway fail loudly at deploy. Needs sign-off, on-duty number, creds (D-11b).
Test 11c — false "SMS sent"Ship now · decoupled
Cause: log-mode no-op is recorded as a send; the transcript is baked before dispatch runs, so a naive conditional is impossible.
Fix: honest first comment + a corrective second comment (proven late-sync pattern); card tells the truth and states the next action.

D-10a · Owner: Gate
Echo the handler's typed words on the confirmation card (not only the ticket)?
Recommend YES — note retention is a trust criterion the handler verifies at their own screen. Low cost: the flow panel already renders the words mid-flow; the card does not.
D-10b · Owner: Gate
Add an optional "notes for the IoT team" outcome-compose field?
Recommend NO for R1 — not needed to fix Test 10 and adds surface. Defer unless the gate wants it.
D-11a-1 · Owner: James + Sam (product call)
Which welfare flows warrant auto-P1?
HeatingP1 on total heat-loss + vulnerable occupants / hard-freezerecommended default
FanP1 on active cooking + gas-safety / extraction failure onlyrecommended default
Hot-waterNOT auto-P1 (edge: care setting)
LightingNOT auto-P1 (premises-dark is a site-electrician matter)
Connectivity / otherNOT auto-P1 — covered by the escape-hatch
Gate accepts or amends. Each "P1" flow implies a new in-flow qualifying step to capture the signal the flow does not capture today.
D-11a-2 · Owner: Gate
Escape-hatch UX — placement and copy of the reason-tagged confirm-prompt.
Recommend a confirm-with-mandatory-reason action on every non-P1 outcome card, tagged operator-override and audited. NOT a bare "escalate as P1" button — so "no auto-P1 button" never means "no P1 path".
D-11b · Owner: James / Spencer (OOHDASH-73 #4)
Go/no-go — enable the real gateway? On-duty number confirmed? Creds present?
Design is switch-on-when-ready. No-go ⇒ 11b defers and 11c ships anyway (the app is truthful in log mode regardless).
