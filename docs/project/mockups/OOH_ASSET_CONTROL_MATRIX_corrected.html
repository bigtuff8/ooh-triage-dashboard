Corrections applied 2026-09-17 (verified against a live write→confirm matrix on the bench): (1) Salus control is setpointDesired only — modeDesired returns failed (not implemented) and hwBoostHoursDesired returns rejected (IT500 DHW only). (2) Intesis has no OnOff or FanSpeed control key — on/off is modeDesired (off=off, any mode=on); fan speed is read-only, not controllable. (3) Multi-gang Tuya — a single switchDesired drives one relay; switch_2 is not addressable yet.

The rule: READ is available for essentially every device. CONTROL is a bounded set — Tuya switch, Salus thermostat, Intesis AC, and (deferred) a TB-native boiler. Everything else is monitor-only. Control = write a <thing>Desired shared attribute (SHARED_SCOPE) → the bridge dispatches to the vendor → confirms <thing>SyncStatus=synced (states: pending→synced, or failed/rejected). Edge-triggered: re-writing the same value does nothing.

Control proven on the dev bench 2026-09-17 via a full write→confirm matrix (values restored after): four Tuya switches (bench-owon-1, bench-tongou-sy1-1/-sy1-2/-sy2-1) → switchDesired → switchSyncStatus=synced, relays audibly clicking; Intesis (funklet-intesis-29d1f022) → setpointDesired → synced; Salus IT700 (spencer-home-salusit700) → setpointDesired accepted (pending), modeDesired=failed, hwBoostHoursDesired=rejected (both by design). Intesis on/off (modeDesired) is unproven: a full off→fan→off→fan→off cycle returned no modeSyncStatus and the unit reports no mode/power telemetry — needs a mode-capable Intesis unit to prove. Confirmed independent: a setpointDesired write does NOT flip power on (setpoint synced, OnOff unchanged). No writes against production. Open items: multi-gang Tuya per-channel addressing and Intesis fan-speed both need a contract change; Intesis on/off needs a bench unit that reports mode/power.
