A cellar cooling unit (gk-6261-cellar-1) is denied; a cellar light / cellar fan is not. The deny fires on refrigeration intent only when no explicit controllable-appliance token is present.

What the fix does, in one screen

  • Classification. A deterministic refrigeration deny at the top of classifyDevice reassigns a cellar/fridge/freezer/chiller/coldroom unit to deviceType:'refrigeration', kind:'fridge', controllable:false — taking precedence over the capability-first switch intent and the name match.
  • Registry. A new refrigeration type with commands:[] means capabilities serialise empty (no button) and the write guard rejects a switch by construction, plus an explicit backstop refusal.
  • Precision. An explicit controllable token — light, fan, socket, or a kitchen appliance — wins over the bare cellar location word, so a cellar light/fan stays switchable.
  • Fail-closed & interlock. When in doubt, monitor-only. Writes stay locked (WRITES_DISABLED="true") throughout; the fix must be observed running live before OOHDASH-19 flips writes on.
